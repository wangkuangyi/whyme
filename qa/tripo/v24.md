| 需求 | 实现与检查结果 |

检查汇总和各项断言保存在 `v24-results.json`。浏览器脚本是 Playwright CLI `run-code --filename` 使用的函数；开发专项使用 5173，生产专项使用 4173。先分别启动 `npm run dev`、`npm run preview`，生产复验前执行构建。图片重生成入口为 `capture-v24-intro.cjs`；`?holdIntro=1` 仅开发模式可用，生产不暴露调试接口。

终审修正了静图背景覆盖节点的问题：节点、连线和拖动标签都位于图片前方。生产层级专项通过逐层隐藏前后的实际截图像素差，确认三个图层有可见贡献，同时检查卡片交互与拖动恢复；不是仅用元素存在或 CSS opacity 作为可见性判断。

本机单场景节点计算取样：Walk 619 帧平均 1.58 ms、P95 2.63 ms；Idle 523 帧平均 0.097 ms、P95 0.232 ms。两段都没有触发画质降级或静帧回退。脚本为 `v24-scene-performance.cjs`，这些数值不代表其他设备的性能保证。

视觉证据位于被 Git 忽略的 `output/playwright/v24/`、`v24-ui/`、`v24-motion/`。已查看桌面与手机开场对照、走路光影、15 张环顾动作与待机取样、手机展开与降级、静帧切换和打印页面。取样并不等于所有尺寸或每一帧均无穿模。生产构建仍有 Three.js 单个 chunk 超过 500 kB 的体积提示；构建成功，没有页面脚本错误或失败资源。
